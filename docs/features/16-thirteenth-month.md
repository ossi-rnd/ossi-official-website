# 16. 13th month pay (PD 851)

Every rank-and-file employee who worked at least a month in the calendar year is owed **1/12 of the basic pay earned in that year**, paid **no later than December 24**. Accounting runs it from **13th Month Pay** (`/thirteenth-month`, `manage-payroll`).

## What counts

| Counts | Doesn't count |
| --- | --- |
| Basic pay on every **generated** payslip of the year (days × daily rate) | Overtime, holiday premium, night differential (Revised Guidelines on PD 851) |
| Minus late deductions (time not worked isn't salary earned) | Adjustments (corrections, allowances, refunds) |
| Payslips of employees who have since left (they get it prorated) | Estimates: a payslip must be generated to count |

```
earned = (basic pay − late deductions in the year's payslips up to "covers until") ÷ 12
amount = earned − what approved 13th month runs of the same year already paid
```

Up to **₱90,000** of 13th month pay and other benefits is tax-exempt (RA 10963). An employee whose earned amount is above that gets an amber "excess taxable" badge, for the year-end tax adjustment. Nothing is withheld here.

## The flow

1. **New 13th month run** → year, *count payslips of periods ending up to* (defaults to the last generated cutoff) and pay date (defaults to Dec 20) → **Compute**. This creates a draft.
2. Review each employee. Click a name to see the cutoffs counted. Use **CSV** for the bank or for checking. **Recompute** after generating more payslips.
3. **Approve.** The amounts are frozen and employees see them under **13th month pay** on My Payslips. If any payslip was generated since the last compute, approval is refused, the draft is refreshed, and Accounting reviews it again. What gets approved is always what was on screen.
4. **Mark as paid** stamps `paid_at` on every payout.

**December's last cutoff.** It usually isn't generated by December 24. Pay the main run covering up to Dec 15. After Dec 31 is generated, create a **balance run** up to Dec 31: it pays only `earned − already paid`. Rules that keep this safe:
- one draft per year at a time;
- a new run must cover later than every approved run of that year;
- only drafts can be deleted.

## Code

- `ThirteenthMonthBasisQuery` (the computation, from `payslip_records`)
- `CreateThirteenthMonthRun`, `RecomputeThirteenthMonthRun`, `AdvanceThirteenthMonthRun`, `DeleteThirteenthMonthRun` (actions; every change is audited as `thirteenth_month.*`)
- models `ThirteenthMonthRun` / `ThirteenthMonthPayout`
- `App\Livewire\Admin\ThirteenthMonth`, plus `MyPayslips::thirteenthMonth()` for the employee side

Each payout stores the cutoffs it was computed from (`cutoffs` JSON), so an approved amount can always be explained.

Tests: `tests/Feature/Payroll/ThirteenthMonthTest.php` covers ₱610 × 8 days → ₱406.67, a balance run of ₱305.00 − ₱101.67 = ₱203.33, refresh-on-approve, and the gate.

**Final pay** ([27](27-final-pay-and-cash-bond.md)): someone who resigns mid-year gets the 13th month pro-rated to their last day. Once released, the year's run counts it as already paid (`earlier_paid`), so it isn't paid twice.

## Not yet

- Payment in two instalments (e.g. half in June). The balance-run mechanism supports it: run one up to May 31, then another later.
