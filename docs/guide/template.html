00

Architecture

Every feature follows one path. A route checks a gate, a thin Livewire component validates and re-checks the gate, an Action applies the business rule inside a transaction and writes the audit entry. Reads go through a Query that fetches in bulk and hands plain data to a pure calculator.

Question you'd askAnswer
Why Actions instead of putting logic in the component?The same rule is reused by the seeder, a console command and tests, and a component re-renders constantly. An Action is a plain class you can call and test without a browser.
Why do Actions throw ValidationException?Livewire catches it and shows the message under the matching field, so components need no try/catch. "Already clocked in" lands under punch.
What is "pure" about the calculators?They take every input as arguments and return a value. No database, no clock, no config. That is why the payroll formula can be unit-tested with hand-written rates.
01

Fortify & HR-only registration

Yes, Fortify is the right tool here. It is headless: it owns the login, reset, verification and two-factor routes and their security details, while we write the views and one hook, CreateNewUser. That hook is where "only employees HR has registered may create an account" is enforced.

Fortify gives usThrottled login, session regeneration, signed verification links, reset tokens, TOTP two-factor with recovery codes.
We addBlade views, the HR-only claim rule, a block on resigned staff, queued emails, a friendlier logout message.
Every attempt is loggedSuccess or failure, with the reason, in the audit log. The person registering only ever sees one generic message.

Why the same error for every failure?"That number exists but the email is wrong" tells a stranger which numbers are real. HR still sees the exact reason in the audit log.
A pilot tester has no real email. What does HR do?Switch on Test account (no real email) when adding them (on Add only; an x-ui.switch, a real checkbox with role="switch" drawn as a sliding track). They register with it, ClaimEmployeeAccount confirms the email at once (no link to click), and User::routeNotificationForMail() returns null so Laravel's mail channel sends nothing there; in-app notices still show. 02

Roles & gates

Ten roles and a set of gates, both PHP enums. The company's leadership is two roles, President and Vice President, with the same access everywhere through Role::leadership() (there's no "Executive": the company doesn't use the word), so either one can approve. They and the Super Admin are accounts without an employee record (Role::withoutEmployeeRecord()): no employee number, payroll, attendance or headcount, created from the console rather than registered, and Roles & Access won't give these roles to someone on payroll. Their My Profile says so in a plain note ("This is a Super Admin account, not an employee: it has no employee number ... It can still open and manage every part of the system": not being an employee doesn't take any access away) instead of the "HR hasn't set up your employee record yet" warning meant for new staff. One match in Ability::roles() decides who opens what. The service provider turns each case into a Gate::define(), routes use Ability::X->middleware(), and every write calls $this->authorize() again. Where a role may look but not touch, viewing and changing are separate gates.

The route already has can:. Why check again in the method?The old app had a bug: a page opened while you held a role kept its buttons working after the role was removed. The in-method check also survives if the component is ever mounted on another route.

Privacy notice & sessions

Five middleware run on every web request, including every Livewire click, because Livewire's update endpoint sits in the same web group. Order matters: the idle check comes first, so a timed-out session is signed out, not sent to the privacy notice.

Question you'd askAnswer
Why both a JS timer and middleware?JavaScript can be disabled or the tab closed; the session cookie outlives both. The middleware enforces, the script warns and syncs tabs.
Can an open tab keep a session alive forever?No. The keep-alive ping only resets the clock when it reports real input (active: true), and the script only sends that after a key press, click or scroll.
Why store the notice version, not a yes/no?When the notice changes, bump PRIVACY_NOTICE_VERSION and everyone is asked again.
Why "acknowledge" and never "consent"?The legal basis is the employment contract and the law. Consent given to keep a job isn't freely given, and calling it consent would invite withdrawing it. The reasoning is in config/privacy.php.

People: employees, shifts, holidays

Question you'd askAnswer
Why is the shift on the profile and not on users?HR assigns a shift before the person has an account. A column on users would have nowhere to live yet.
What happens if APP_KEY changes?The encrypted columns can't be read. Back the key up, and use APP_PREVIOUS_KEYS if you ever rotate it.
Why the $attributes defaults on models?Laravel does not read the row back after create(), so a database default isn't on the PHP object. With strict mode on, reading it would throw.
How does an overnight shift work?An end time before the start time means it ends the next day. crossesMidnight() and scheduledMinutes() handle it.

The form: hire type and the client site

Under one Client site heading, Region narrows Province, which narrows Detachment, and nothing new is stored: the region and province are the client's. areaChanged() keeps the three consistent from each page's updatedForm hook (a new region clears the province; a narrower area drops a detachment outside it; picking a detachment fills in its area), so a hidden choice can never be saved.

The employee number is generated

The employee number is the OSSI ID card's control number, made by the same rule as the ID card app: the hire date as YYMMDD, the province of birth code (ISO 3166-2:PH, 82 provinces plus NCR for Metro Manila), a dash, 4 random digits, and -RH for a rehire, e.g. 260627PAM-0950. HR fills the hire date and province, and the form shows 260627PAM-····; EmployeeNumber::generate picks the digits on save, from the ones still free for that date and province, so it never repeats. A person who already has a printed card gets the card's number instead: "Enter the card's number" checks the format and fills the hire date and province from it, so the two can't disagree. Editing keeps the number, because it's the card's identity and what they registered with.

Government IDs take digits only, in the agency's pattern. SSS is 10 digits (00-0000000-0), the PhilHealth PIN 12 (00-000000000-0), the Pag-IBIG MID 12 (0000-0000-0000), and the TIN 9 (000-000-000), plus a 3- or 5-digit branch code if the card shows one. While HR types, formatGovernmentId drops anything that isn't a digit and adds the dashes. On save, GovernmentId::format() tidies spaces and dashes the same way, and a closure rule refuses letters or a wrong length with a plain message ("SSS No. has 10 digits (00-0000000-0); this one has 9."). A blank field is allowed, since a new hire may not have every number yet. One list, GovernmentId::FORMATS, drives the rules, the placeholders and the dash pattern, so they can't disagree.

07

Leave & overtime

Employees file, supervisors decide: guards' leave climbs Operations to HR, and their overtime goes to HR, Admin or Operations (a Satellite only in its region). Office staff's leave and overtime go to their head (App\Support\Heads, the owner's chain): HR for Admin and others; Operation HQ for a Satellite; the President or VP for HR, Operation HQ and Accounting. The President or VP still see them all, and HR sees every non-HR staffer's (view only). Reviews lock the row so two supervisors can't both decide, nobody reviews their own request, and approved overtime can be less than requested, never more. Payroll later pays the smaller of logged and approved overtime, day by day.

One chain of headsApp\Support\Heads answers both "who heads this person" (of, label) and "does X head Y" (isHeadOf). It covers a guard → Operation HQ + the region's Satellite; HR, Operation HQ and Accounting → the President or VP; a Satellite → Operation HQ; anyone else in the office (Admin…) → HR. Operation HQ and Accounting first sat under HR. The owner moved them after comparing with how agencies usually run: Operations and Accounting answer to the President / GM, while HR administers leave rather than heading other departments. So HR keeps a view-only window on every non-HR staffer, and Heads::toTell copies HR on their attendance alerts. Leave, overtime, time away, attendance alerts, Notices to Explain and merits all ask it, so the chain lives in one place. A Satellite's leave waits at stage hq, where Operation HQ decides it rather than endorsing it on to HR as for a guard. ChainOfHeadsMatrixTest asks all five flows at once for each pair: a head acts for their own people, never upward, sideways, across the chain or for themselves. It found one hole: the President has no employee record, so they fell into the default group and HR counted as their "head". Now nobody heads the Super Admin, President or VP.

Question you'd askAnswer
How is cancelling someone else's leave prevented?The id is looked up through the user: $user->leaveRequests()->findOrFail($id). Another person's id is simply not found.
Why snapshot the post onto the overtime request?So reassigning the guard later doesn't rewrite where they actually worked that night.
Who gets a guard's overtime request?Operations, automatically: Operation HQ and the guard's region's Satellite Operation are told (SubmitOvertimeRequest::operationsFor). Office staff's goes to their head (Heads::of). Employees used to pick a supervisor from a list, which was an extra step and an easy mistake (the wrong person, or one who couldn't approve it). Who decides is still by role; lists show Sent to.
Which leave needs a document?Sick leave from 2 days (a medical certificate), and the leaves under special laws: maternity, paternity, solo parent, VAWC and special leave for women, each with its proof (LeaveType::document()). Vacation and emergency don't: there's nothing to prove, and asking only slows people down.
Can someone file sick leave after the fact?Yes, up to 7 days after it started (sick and emergency only). They're sick first and file once back, attaching the certificate then. Everything else starts today or later.
Who decides the 2 days and the 7 days?HR, in the app: Leave Requests → Rules → Change. Saved as a Setting and audited (SaveLeaveRules, LeaveRules), and My Leave reads the same numbers. Company policy belongs with the people who run the company, not in a server file.
What if the document isn't there yet?It can be attached later from My Leave, and whoever acts next is told again. The decider can still reject, but Approve stays locked with "Waiting for the document" (ReviewLeaveRequest::approvalBlockedReason).
Why not enforce the law's day counts?The laws count days differently (calendar or working days). The form shows the entitlement, and a longer request is flagged to the approver ("This asks for more"), who decides. A wrong hard limit would refuse a lawful leave.
Who can open the documents?The employee and whoever decides: HR for guards, the President or Vice President for office staff (LeaveRequest::documentsVisibleTo). Medical papers are sensitive personal information, so endorsers see only that a document is attached, and the decider's views are audited.
Why is VAWC handled differently?RA 9262 keeps these records confidential. VAWC leave skips the endorsers and goes straight to the decider, and it's hidden from everyone else's list (LeaveRequest::scopeVisibleTo). The bell and email say only "Confidential leave".
Operations knows a guard stayed 3 hours longer. Does the guard have to file it?No. Add extra time on Overtime Requests records it for them (RecordOvertime): saved approved, filed_by Operations, audited, and the guard is told ("Extra time added"). Lists show Added by …. If the guard already asked for that day, Operations is sent to review that request instead: one per day.
Couldn't that pay hours nobody worked?No. Payroll pays the smaller of approved and clocked overtime, day by day, so the guard's own clock-out is still the ceiling. Recording it as an ordinary approved request means payroll needed no change.

What a resigned employee gets at the end: the pro-rated 13th month, plus the cash bond refund, plus or minus Accounting's adjustments, minus what they still owe (the resignation's acknowledgement is the written authorization). Art. 113 asks for written authorization, and it's one of the required "Before you send" lines, so there's no optional box to skip. A paper letter needs their signed authorization (HR ticks it). Notices to Explain

Due process before a real sanction: the twin-notice rule (Labor Code Art. 297–299; King of Kings Transport v. Mamac). The first notice says what happened, the rule, the possible penalty, and gives at least 5 calendar days to explain. The second notice is the decision with its reasons. The system enforces the order; it can't be skipped.

stateDiagram-v2
  [*] --> issued: 1st notice (acts, rule, penalty, ≥ 5 days)
  issued --> explained: written explanation (+ hearing request)
  issued --> ready: the days pass, no explanation
  explained --> decided: 2nd notice: decision + reasons
  ready --> decided
All four, or no noticeVague charges fail due process. IssueNoticeToExplain requires the specific acts (what, when, where, who saw it), the rule, the possible penalty, and an explain-by date at least 5 days out. A shorter date is refused with the earliest allowed one.
No decision before their chanceNoticeToExplain::readyToDecide() is true only once they've explained or the days have passed. The decision form doesn't show before that, and DecideNotice refuses it too.
Received isn't agreeing"I received this notice" and "I received the decision" are the proof of service. They're kept with the time; writing an explanation counts as receiving.
Nothing automatic afterA dismissal tells HR to set Terminated and start the clearance and final pay; a suspension simply has no attendance to pay. A demerit can go with the decision (chapter 30).
WhoGuards: Operation HQ, or their region's Satellite (the roadmap's "Operations only" holds for guards). Office staff: HR. HR staff: the President or Vice President. HR and the President or Vice President read them all; other HR staff never read an HR member's.

Patterns & lessons

The decisions that keep coming back, and the mistakes made along the way, so the next feature starts from them instead of relearning them. Each pattern names where it lives in the code.

Patterns to reuse

Suggest, then a person decidesWhen money depends on judgment, the app suggests and Accounting accepts or dismisses with a reason. It never adds pay silently. Examples: corrections from earlier cut-offs (DetectPriorPeriodCorrections), paid leave (DetectPaidLeave), reliefs to claim. The suggestion holds the payslip until decided, is idempotent (one row per source and run), and is never re-suggested once decided.
No deduction without a basisLabor Code Art. 113: the employee's written authorization (ticked in the app, or a signed paper) or the law (SSS/Pag-IBIG loans). The exact sentence is saved with the time. Used by loans (DeductionAuthorizationBasis), Borrow Load and the resignation's final-pay consent. Without a basis, nothing is taken; the debt is shown instead.
Acknowledge briefly, keep the wordsOnly forms that commit someone to something get an acknowledgement: resignation, complaint, reimbursement, Borrow Load and loans. Routine requests waive nothing and get none; more checkboxes teach people to tick unread. It's 3–7 plain sentences and a required tick, saved word for word with the time, in English or Filipino (lang/*/acknowledgements.php, partials.acknowledgement, partials.acknowledged).
Policy numbers belong to the people who own themCaps and day limits are company policy, so the owner sets them in the app, not a developer in .env. They're stored in the settings table, written only through an audited Action, and read through one helper with starting values in config (Reimbursement::limits() by Accounting, LeaveRules by HR). Forms read the same helper, so their text can't drift from the rule. Only infrastructure (disks, keys) stays in env.
Link records, one standing per sourceWhen one record follows from another, keep a link both ways and allow one standing child, enforced under a row lock. Examples: a relief and its fare claim (absence_notice_id), a just-cause resignation and its complaint (resignation_id). The page then shows the child's status where people look.
Confidential by designSensitive papers (medical, VAWC) are private files opened only by the employee and whoever decides, and every other view is audited (LeaveRequest::documentsVisibleTo). VAWC skips the endorsers, is hidden from other lists, and emails say only "Confidential leave". Decide who must not see something before building the screen.
Close things, don't delete themA state that ended badly is still a fact: "Not covered", "Dismissed: reason", "You didn't agree", "Withdrawn". Records stay for the audit and the client. A daily command moves stale states on (app:close-uncovered-absences), so lists stay clean.
Speak to the readerThe same fact reads differently to each person: "Authorized by them in the app" (Accounting) versus "You authorized it in the app" (the employee); "Serious insult on my honor" on the employee's form versus "on their honor" for HR. Give the enum one label per audience (labelForEmployee, labelForOthers).
Don't store what a value already saysThe province of birth is in the employee number's letters, so it's read from there (EmployeeNumber::provinceCode()), not saved again in a column that could disagree. The dropdown is just a way to fill in the letters. Likewise "expired" is computed from expires_on.
Invite proof, don't demand itWhen a requirement would block the people a feature exists for, offer it instead: an optional upload, a "who saw it" field, and a way for the handler to ask later. Complaints work this way; leave documents block approval only because the law ties those leaves to a document.
One list, narrowed by tabsWhen two kinds of people share a page, keep one search and add tabs with counts, not two search boxes. The list and its counts come from one base query, so they always agree, and the gate decides who gets the tabs at all (Employees, Leave and Overtime Requests: view-office-staff).
